## WP Playground dev environment

Generated by `krokedil-playground init --update` — edits between the markers will be overwritten. Config: `playground.config.mjs`; full docs: `node_modules/@krokedil/wp-playground-tools/README.md`.

- `npm run playground:start` — persistent dev site on :8910 (worktree-isolated; `--fresh` reprovisions)
- `npm run playground:server-development` / `-demo` — ephemeral servers on :8911 / :8912
- Forward extra flags after a `--` separator (npm requires it): `npm run playground:start -- --xdebug` (also `--phpmyadmin`, `--php=8.2`, `--wp=6.8`)
- Pick the transport per run, cheapest that fits (any flag with any mode): plain http for admin/UI/backend work; `--https` for checkout and anything needing `is_ssl()`/a secure context; `--tunnel` only when the provider must reach the site (webhooks, hosted-page redirects)
- `--tunnel` — public https URL via ngrok (for webhooks/callbacks); `--https` — local mkcert https on the mode port +400
- `--tunnel-domain=<host|none>` — per-run tunnel domain override (implies `--tunnel`); use for a second simultaneous worktree: another reserved domain, or `none` for an ephemeral URL
- **Active proxy URL** (`--tunnel`/`--https`): read `.playground/proxy-url.txt` — the file exists only while a proxy runs. ngrok request inspector/replay: http://127.0.0.1:4040
- Login: `admin` / `password` — development mode auto-submits the wp-login form as admin for **local** requests only (curl checks won't consume it; `wp-login.php?action=login` forces the form locally)
- Over a `--tunnel` URL the site is public: the tunnel guard refuses `password` and requires the run's tunnel password (printed with the public URL, or `KROKEDIL_PG_TUNNEL_PASS`). Storefront, REST and webhooks stay open
- **Logged-out testing**: `?krokedil-guest=1` on any local URL logs out and stops auto-login for 12 hours in that browser/cookie jar (front-end login links would otherwise sign you back in); `?krokedil-guest=0` restores it. Per browser, development mode only, and it clears the cart
- Logs/DB of the persistent site: `~/.wordpress-playground/sites/<sha256(cwd)>/wp-content/` — `debug.log`, `uploads/wc-logs/`, SQLite at `database/.ht.sqlite`
- Secrets (API keys read via `envSecret()` in the config) come from env files, first hit wins: ambient env > the repo's gitignored `.env` > main checkout `.env` > `~/.config/krokedil-playground/.env` (central, shared by all plugins). `npm exec krokedil-playground credentials` lists the names and stubs missing ones in the central file
- `.playground/` is generated (blueprints + staged assets, gitignored); write blueprints for inspection with `npm exec krokedil-playground compose`

### Plugin-specific notes

- **Kustom Checkout needs https.** The gateway refuses to run over plain http (the settings screen shows "You need to enable and configure https…" and the checkout iframe fails to initialise), so `--https` is the default transport for this plugin, not an occasional extra: `npm run playground:start -- --https` → https://localhost:9310. Plain http is only useful for non-checkout admin work.
- `--tunnel` on top of that for anything where Kustom must reach the site (checkout callbacks, push notifications, order-management webhooks).
- Test credentials: `KCO_TEST_MERCHANT_ID_EU` / `KCO_TEST_SHARED_SECRET_EU` (see `.env.example`). Without them the gateway is active but unconfigured — the cart page shows a raw `PERMISSION_DENIED` payload from the Kustom API and the console logs "Failed to initialize Kustom Checkout". Add the values, then reprovision with `--fresh`.
- Provisioning runs `composer install`, which makes wpify-scoper wipe and regenerate `dependencies/` — that deletes the tracked `dependencies/.gitkeep`. Restore it with `git checkout -- dependencies/.gitkeep` before committing.
